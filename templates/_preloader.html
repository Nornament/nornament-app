{% load static %}{% comment %} The splash between navigations. Included by both shells. Two different waits, and it has to cover both: - rendering the new document, which is what a load-time splash covers, and - the server round trip, which it cannot — while a form is posting, the browser is still showing the OLD page and the new document does not exist yet. That is the longer wait of the two (uploading a workbook, running a report), so the splash is also raised on submit and on link clicks, before navigation begins. It shows immediately and stays for at least MIN_MS. Most screens here render in well under a tenth of a second, so anything that waits before appearing simply never appears, and anything that leaves the instant the page is ready reads as a flicker rather than a splash. Holding it for a beat is what makes it look deliberate. That beat is real added latency on a fast page — a deliberate trade, and MIN_MS is the dial. Its CSS is inline because an external stylesheet has not necessarily arrived at first paint, and a splash that itself flashes unstyled is worse than none. A CSS animation retires it after eight seconds if the script never runs at all: a splash that can outlive its own JavaScript is a site nobody can use. {% endcomment %}
